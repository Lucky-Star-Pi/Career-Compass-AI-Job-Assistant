## 2. 如何证明可信

1. **数据可追溯。** 每条包含source_url、obtained_at、raw_snapshot、evidence_hash，可定位到[10份证据TXT](../data/raw/MANUAL-20261030-220241.pages/)并重算SHA256。[结构化数据](../data/processed/jobs.json)保留来源与条件原文；哈希证明提交证据的一致性，不证明招聘方此刻仍开放。
2. **判定与解释分离。** 三态由[规则函数](../app/lib/match.ts)计算，画像未确认为unknown、任一明确不符为ineligible、关键未知保持unknown。AI负责解释，卡片判定不由生成文本改写；分项计数聚合已有checks，来源核对不计作个人条件通过。
3. **回答有引用且服务端校验。** [chat-output.ts](../app/lib/chat-output.ts)检查引用非空、ID与URL成对匹配且属于候选集，并拒绝reply内URL和承诺用语。截断JSON仅重试一次，两次失败或引用不合格则降级；这些闸门不能证明所有自然语言结论正确。
4. **不编造缺失条件。** 没有可用候选或引用无效时不输出成功的岗位推荐，走降级提示；当前无匹配原因未细分。[数据契约](../data/CONTRACT.md)规定页面未写保留unknown，绝不将缺失改写成“不限”；原文明示的长期招聘保留原句，不伪造截止日期。
5. **评委可逐项复核。** 可点击卡片“打开原始详情”，对照来源、获取时间、原文与规则解释。[校验入口](../scripts/validate_data.py)及[规则测试](../app/lib/match.test.ts)提供机器检查，已知局限与原始记录缺失在本说明披露，复核不依赖模型自行给出的可信度分数。

## 4. 未完成与已知问题

- 当前支持粘贴简历要点，原文仅在账号私有文件保存、可删除；不支持PDF、扫描件和OCR。公开demo多人共享，不适合真实简历。
- 当前提供注册、登录和7天签名会话；画像与最近20条消息按账号保存在应用目录外的文件中。没有找回密码、邮箱验证或多进程数据库锁。
- 未接数据库，应用只读app/lib/jobs.json；源数据变化需同步副本并重新构建。
- 仅10条；按参赛者说明，覆盖“央国企校招筛选前10条”的人工详情URL样本，不是全站、不宣称覆盖所有符合条件岗位。
- 轮询式部署不是标准托管CI；每分钟检查版本，更新存在构建延迟，推送与上线不是同一个时刻。
- 招聘方可能提前关闭报名；显式长期招聘没有具体截止日期，不保证评审期间仍开放，也不证明用户可报名。
- 附件与原始公告正文未系统采集，报名入口、学位、年龄等仍有缺口。
- 当前持久化最近20条消息，含独立账号的连续追问；未实现多会话管理、无限历史或整份简历的通用问答。
- 硕士能否报只写“本科”的岗位仍按unknown处理；专业目录、附加限制、证书缺失需人工确认，没有为提高通过数放宽规则。
- “公告未载明”计数直接聚合unknown，可能包含画像未提供或条款解释空间，不能将所有计数都理解为原公告确实缺字；逐项解释保留具体原因。
- 生成文本可能偏离证据；引用闸门与提示词不能替代逐句事实核查。模型失败走降级，降级不算真实调用成功。
- 模型限额仅单进程内存计数，重启会重置；未配置持久费用监控，账户余额及未来7天额度未由本次工具核验。
- 当前入口为HTTP，未配置HTTPS，请只用独立测试密码及脱敏求职要点，省略身份、住址和联系信息；不要把演示入口当作敏感材料保险箱。
- 早期阶段报告保留当时零数据/来源未核对等历史状态；当前数据以本次结构化文件和提交标记为准，不将历史快照改成事后完成。
